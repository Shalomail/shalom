So funktioniert die Verschlüsselung

Shalom Mail ist ein E-Mail-Dienst unter shalomail.com. Deine gespeicherten E-Mails sind mit einem Schlüssel verschlossen, den nur dein Passwort entsperrt, und zwischen Shalom-Konten ist alles Ende-zu-Ende verschlüsselt. Hier steht, wie das funktioniert, in einfachen Worten, und wo der Schutz endet.

Dein Schlüssel entsteht auf deinem Gerät

Wenn du ein Konto erstellst, erzeugt dein Browser deinen privaten Schlüssel: 256 zufällige Bits, für X25519. Er erreicht den Server nie in einer Form, die jemand lesen kann.

Der Server bewahrt ihn nur in einem Umschlag auf, der mit deinem Passwort verschlossen ist, und der Umschlag wird beim Anmelden auf deinem Gerät geöffnet. Zusätzlich legt der Server ein zweites, eigenes Schloss um diesen Umschlag, mit einem Geheimnis, das außerhalb der Datenbank liegt.

Dein Passwort bleibt auf deinem Gerät

Dein Gerät schickt das Passwort durch Argon2id, mit 128 MB Speicher und 3 Durchläufen, und leitet aus dem Ergebnis zwei Schlüssel ab. Der eine beweist dem Server, dass du das Passwort kennst. Der andere öffnet den Umschlag mit deinem Schlüssel. Das Passwort selbst wird nie gesendet.

Der Server speichert nur einen Code, der aus diesem Nachweis entsteht, mit einem Geheimnis, das nicht in der Datenbank liegt. Die App prüft außerdem die Argon2id-Einstellungen, die der Server schickt, und lehnt schwache ab, damit ein manipulierter Server dein Passwort nicht leichter erratbar machen kann.

Jede gespeicherte E-Mail ist versiegelt

Jede E-Mail wird in zwei versiegelten Teilen gespeichert: einem kleinen Kopf mit Absender, Empfängern, Betreff, Datum, einer kurzen Vorschau und der Unterhaltung, zu der sie gehört, und der vollständigen Nachricht mit ihren Anhängen.

Beide Teile werden mit X25519, HKDF-SHA256 und AES-256-GCM für deinen öffentlichen Schlüssel versiegelt. Nur dein privater Schlüssel öffnet sie, der Server bewahrt also Daten auf, die er nicht lesen kann.

E-Mails mit anderen Anbietern

E-Mails von Gmail, Outlook oder jedem anderen Anbieter kommen unverschlüsselt an, wie jede E-Mail im Internet. In diesem Moment prüft der Server nur, ob die Domain des Absenders ihn bestätigt, und versiegelt sie mit deinem Schlüssel. Ob es Betrug oder Werbung ist, prüft dein Gerät, das sie mit deinem Schlüssel öffnet. Die unverschlüsselte Fassung wird nicht gespeichert.

E-Mails, die du an andere Anbieter schickst, gehen als normale E-Mail hinaus. Der Server leitet sie unverschlüsselt weiter, und der Anbieter des Empfängers kann sie lesen. Hier schützt Shalom die Kopie in deinem Postfach, nicht den Weg.

Zwischen Shalom-Konten: Ende-zu-Ende

Wenn du an eine andere Shalom-Adresse schreibst, versiegelt dein Gerät die Nachricht für den öffentlichen Schlüssel des Empfängers, bevor sie losgeht. Lesen lässt sie sich nur auf dem Gerät des Empfängers, nie unterwegs und nie auf dem Server.

Die Nachricht wird außerdem mit deinem eigenen Schlüssel authentifiziert, der Server kann also keine Nachricht in deinem Namen fälschen.

Auch der Absender ist versiegelt, nach dem Vorbild von Signals Sealed Sender. Der Server gibt jedem Konto ein kurzes Zertifikat, signiert mit Ed25519. Dein Gerät legt es in das Siegel, der Empfänger prüft es, und der Server speichert und stellt die Nachricht zu, ohne zu wissen, wer sie geschickt hat.

Um Missbrauch zu begrenzen, ohne zu erfahren, wer was geschickt hat, verbraucht jede Zustellung ein Ticket, das der Server blind signiert hat, mit RSA-Blindsignaturen. Der Server prüft das Ticket, kann es aber nicht mit dem Konto verbinden, das es angefordert hat.

Den Schlüssel eines Kontakts prüfen

Die App merkt sich den Schlüssel jedes Shalom-Kontakts, wenn sie ihn zum ersten Mal sieht. Falls der Server jemals einen anderen Schlüssel für dieselbe Adresse liefert, stoppt das Senden, und die App zeigt beide Fingerabdrücke mit je 30 Ziffern, damit du sie mit deinem Kontakt vergleichen kannst. Auch das shalom-CLI hält an, wenn sich der Schlüssel eines Kontakts ändert, bis du es bestätigst.

Postfächer für KI-Agenten

Jedes Agenten-Postfach hat ein eigenes Schlüsselpaar, erzeugt auf dem Rechner, auf dem du das shalom-CLI oder das Node-SDK nutzt. Der private Schlüssel bleibt in ~/.config/shalom oder im SHALOM_AGENT_TOKEN, den du exportierst. Bewahre dieses Token deshalb als Geheimnis auf.

Der Schlüssel deines Kontos kann Agenten-Postfächer erstellen und löschen, aber keines davon öffnen. Der Schlüssel jedes Postfachs liest und sendet nur über dieses Postfach.

Was der Server weiß

Um zu funktionieren, muss der Server einiges wissen. Nichts davon ist der Inhalt deiner gespeicherten E-Mails:

  • Deine Adresse, der Name, den du gewählt hast, und, falls du eines hinzufügst, dein Profilbild.
  • Deine Wiederherstellungs-E-Mail, verschlossen aufbewahrt und nur geöffnet, um dir einen Link zu schicken.
  • Zu jeder Nachricht: für welches Postfach sie ist, wann sie ankam, wie groß sie ist, in welchem Ordner sie liegt und ob sie gelesen, angeheftet oder markiert wurde.
  • An wen du bei anderen Anbietern schreibst, denn diese E-Mails gehen als normale E-Mail hinaus.
  • Deine verbundenen Sitzungen: wann jede begonnen hat, wann sie zuletzt genutzt wurde und welcher Browsertyp.

Die vollständige Liste, mit der Speicherdauer für jeden Punkt, steht in der Datenschutzerklärung.

Wo der Schutz endet

  • E-Mails mit anderen Anbietern sind nicht Ende-zu-Ende verschlüsselt. Sie reisen als normale E-Mail, und der Server sieht sie in dem Moment, in dem sie durchlaufen.
  • Wenn du dein Passwort vergisst, lassen sich deine gespeicherten E-Mails nicht wiederherstellen, denn nur dein Passwort öffnet deinen Schlüssel und Shalom hat keine Kopie davon. Mit deiner Wiederherstellungs-E-Mail kannst du ein neues Passwort festlegen und deine Adresse behalten, aber das Postfach beginnt leer.
  • Die App läuft in deinem Browser und wird von shalomail.com geladen. Wie bei jeder E-Mail, die im Web funktioniert, verlässt du dich darauf, dass die Seite den hier beschriebenen Code ausliefert.
  • Verschlüsselung kann kein Gerät schützen, das bereits kompromittiert ist. Wenn du dir ein Gerät merken lässt, bleibt dein Schlüssel in diesem Browser. Schütze es also wie dein Passwort.
  • Der versiegelte Absender hält den Absender aus dem heraus, was der Server speichert. Wie jede Website sieht der Server trotzdem die Verbindung hinter jeder Anfrage und nutzt sie nur gegen Missbrauch, wie die Datenschutzerklärung erklärt.
