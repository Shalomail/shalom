Build on Shalom Mail

Give software its own end-to-end encrypted email address. Use the CLI from a terminal, the Node SDK from your code, or the HTTP API from anything else. Encryption always happens on your side: the server stores and relays sealed data it cannot read.

Three ways in

CLI
npm install -g shalomail, then shalom login and shalom agents create yourname-bot. Every command speaks JSON. Commands
Node SDK
import { Agent, Account } from 'shalomail'. Reads, seals and sends on your machine. Node.js 20 or newer.
HTTP API
JSON over HTTPS at https://shalomail.com/api. Message heads and bodies travel sealed, so you seal and open them yourself (format below).

Node SDK

The package that installs the CLI is also the library. An agent mailbox opens from its token (shalom agents export <address>) or from the file the CLI saved.

import { Agent } from 'shalomail';

const agent = Agent.fromToken(process.env.SHALOM_AGENT_TOKEN);

for (const m of await agent.inbox({ unread: true })) {
  const msg = await agent.read(m.id);
  await agent.reply(m.id, { text: `Got it: ${msg.subject}` });
}

for await (const msg of agent.watch()) {
  console.log(msg.from?.address, msg.subject, msg.text);
}

Create and delete agent mailboxes with your account key (from shalom login, or SHALOM_API_KEY). The mailbox private key is created in your process and comes back inside the token: store it as a secret.

import { Account, Agent } from 'shalomail';

const account = new Account(process.env.SHALOM_API_KEY);
const { address, token } = await account.createAgent('billing-bot', {
  displayName: 'Billing',
});

const bot = Agent.fromToken(token);
await bot.send({
  to: 'ana@example.com',
  subject: 'Invoice 1042',
  text: 'Attached.',
  attachments: [{ filename: 'invoice.pdf', content: pdfBytes }],
});
agent.inbox(opts)
Summaries of a folder: folder, limit (up to 100), unread.
agent.read(id)
The full message: text, html, attachments with their bytes, Message-ID and thread headers, and verifiedSender for mail from other Shalom accounts. Marks it read unless { markRead: false }.
agent.send(msg)
To Shalom addresses it is sealed end to end and delivered with a sealed sender; to anyone else it goes as regular email. A copy is sealed into Sent.
agent.reply(id, msg)
Same thread, with Re:, In-Reply-To and References. all: true replies to everyone.
agent.move(ids, folder)
inbox, archive, spam or trash.
agent.mark(ids, change)
{ read, starred }.
agent.watch(opts)
Async iterator of new inbox messages, polling every 15 seconds by default. Stop it with an AbortSignal.
account.createAgent(name)
Creates name@shalomail.com and returns { id, address, token }.
account.listAgents()
Your agent mailboxes and your plan.
account.deleteAgent(address)
Deletes the mailbox and all its mail. The address stays reserved for you.

Errors throw ApiError with status and code. Types ship with the package.

Authentication

Two kinds of API key, both sent as Authorization: Bearer <key>:

  • Account key (shalom_sk_...): creates agent mailboxes, lists them and shows the plan. It cannot open, send for or delete a mailbox on its own, and it cannot touch billing. Get one with shalom login, or create one for a server on the AI agents page of the app.
  • Agent key (shalom_ak_...): reads and sends for one agent mailbox only. Issued when the mailbox is created and rotated with shalom agents rotate.

Every request that changes something must also send x-shalom: 1 and a JSON body. Responses are JSON; errors are { "error": "code", "message": "..." }.

curl https://shalomail.com/api/agents \
  -H "Authorization: Bearer $SHALOM_API_KEY"

HTTP API

Agent mailboxes (account key)

GET /api/agents
{ agents: [{ id, address, name, createdAt, paused }], plan: { plan, limit, used } }
POST /api/agents
Body { address, name, publicKey }, where publicKey is the base64 X25519 public key you generated. Returns { agent, key } with the new agent key.
POST /api/agents/delete
{ id, agentKey }. Deletes the mailbox and its mail. With an account key it also needs the mailbox's own agent key, so a leaked account key cannot destroy mailboxes.
POST /api/agents/rotate
{ id }. Returns { sealedKey }: the new agent key sealed (purpose raw) to the mailbox public key, so only the holder of its private key can open it. The old agent key stops working.
GET /api/billing
Plan, limit, mailboxes in use and renewal date. Subscribing and changing plans happen only in the app, signed in: API keys cannot touch billing.

Mail (agent key)

GET /api/messages
Query folder (inbox, starred, sent, drafts, archive, spam, trash), limit (1 to 100), before (a received_at for the next page). Returns { messages: [{ id, folder, seen, starred, received_at, size, sender, head }], more, counts }; head is the sealed head in base64.
GET /api/messages/{id}/raw
The sealed body, as bytes.
POST /api/messages/update
{ ids, seen?, starred?, folder? }, up to 90 ids.
POST /api/messages/delete
{ ids }. Only for messages already in trash or spam.
POST /api/send
Recipients outside Shalom (to, cc, bcc) with subject, text, html, attachments (base64) and thread headers, plus sentCopy: { head, raw }, your copy sealed to your own key. Shalom recipients are delivered separately with /api/deliver.
POST /api/cert
A sender certificate for your address and key, signed by the server (Ed25519), valid for 7 days.
POST /api/tokens
{ blinded: [...] }, up to 20 blinded delivery tickets; returns { signed }. Counted against your daily limit, then used anonymously.

Public

POST /api/keys
{ address }. The public key of a Shalom address, or null. Send it without credentials.
POST /api/deliver
{ to, head, raw, token, sig }. Anonymous delivery to a Shalom address, paid with one delivery ticket.
GET /api/auth/config
The server's public keys: certKey (Ed25519, for sender certificates) and tokenKey (RSA, for tickets). Pin them on first use.
POST /api/cli/start, /api/cli/poll
Browser login for command line tools: start returns a code and a link, poll returns the account key sealed to the public key you sent.

Encryption format

Every mailbox has an X25519 key pair. The private key never reaches the server. Each stored message has a sealed head (a small JSON with from, to, subject, date, snippet and a thread marker) and a sealed body (the full MIME message, gzip compressed).

A seal is version (1 byte) | ephemeral public key (32) | nonce (12) | ciphertext + tag. Version 1: X25519 between a fresh ephemeral key and the recipient key, HKDF-SHA256 with salt ephemeralPub || recipientPub and info shalom/v1/head or shalom/v1/raw, then AES-256-GCM with the same info as associated data.

Mail between Shalom accounts uses version 3: the content is sealed with an extra DH between the sender and recipient keys (in the style of HPKE Auth mode) and carries the sender certificate inside the seal, so the server cannot forge or read who sent it. The recipient verifies the certificate with the server certKey. Delivery tickets are RSA blind signatures with a full-domain hash, so the ticket cannot be linked to the account that requested it.

The SDK implements all of this. If you need another language, write to contato@shalomail.com.

Errors and limits

bad_key 401
Invalid or revoked key.
key_scope 403
The key cannot do this: account keys manage agents, agent keys read and send.
agent_limit 402
The plan has no free agent mailbox left.
agent_paused 402
The mailbox is over the plan limit: it still receives and can be read, but cannot send.
send_limit 429
Daily limit for this mailbox.
slow_down 429
Too many requests in a minute.
  • Messages up to 15 MB. To outside addresses: up to 50 recipients and 4 MB of attachments per message.
  • Per mailbox and day: 20 outside recipients in the first week and 100 after that; 100 Shalom deliveries in the first week and 500 after that.
  • Each mailbox has 1 GB. Trash and spam empty themselves after 30 days.
  • No webhooks yet: use agent.watch(), shalom watch --exec, or poll GET /api/messages.

Shalom Mail (shalomail.com) is an encrypted email service that works in the browser. Stored email is locked with a key that only exists on your device, and mail between Shalom accounts is end to end.
